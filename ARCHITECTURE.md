# Архитектура самостоятельного 1c-designer-mcp

## Граница продукта

В проект входит MCP-мост к Конфигуратору: сеанс, поиск/контекст, чтение, планирование точного изменения, изменение и readback, lifecycle/диагностика. Возможности форм, макетов, метаданных, сохранения и отладки добавляются отдельными принятыми маршрутами.

Бизнес-правила медицинской конфигурации, СМС, прикладные обработки и схемы публикации AH_1C в ядро не входят.

## Целевые слои

1. server — публичные MCP tools и схемы аргументов; без загрузчиков и строк подключения в инструментах.
2. core — контракты снимков, диапазоны/Unicode, версии/CAS, результат операции, явное завершение и безопасные ошибки.
3. backends/windows_8_3_18 — native-доступ к конкретной платформе, ABI/SDK, GUI-thread и владение ресурсами. Поддержка версии объявляется по фактической проверке.
4. profiles — локальный выбор процесса, источника, разрешённого объекта, state directory, SDK и политики записи. Реальные параметры и исторические квитанции не входят в общий пакет.

Целевая схема: MCP → core → versioned backend → собственный выбранный процесс Конфигуратора. Локальный профиль передаётся владельцем backend через доверенную конфигурацию, не извлекается из случайного MCP-аргумента и не создаёт разрешение на запись.

## Перенос текущего прототипа

- native_mcp/*: отделить публичные инструменты/контракты от Windows-публикации и Root ownership.
- research/live_editor_operation.py и native-компоненты: заменить фиксированный root/fixture/historical receipts на явный конфигурационно-независимый профиль и новый протокол сеанса. Сохранить проверку личности, владельца, baseline, результата и завершения.
- Привязки Root к private publications и receipts: вынести в локальное состояние установки. Исторические результаты одного проекта не становятся разрешением другого экземпляра.
- Нынешние имена AH1C в magic/versioned wire не заменять косметически: это изменение протокола и требует отдельной версии и совместимых тестов.
- Стабилизировать один сквозной read→edit→readback→close маршрут, затем переключить использующий проект на единственную новую кодовую базу. У работающего прототипа до этого пути не переименовывать.

## Критерий самостоятельности

Чистый checkout на другом рабочем ПК, согласованный SDK/профиль и собственная безопасная fixture позволяют запустить один документированный MCP-entrypoint, прочитать и изменить точный модуль, получить независимый readback и завершение без AH_1C, его дисковых artifacts и старых operationId. Пока это не проверено, portable_native_runtime_verified остаётся false.
