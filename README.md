# 1c-designer-mcp

MCP-мост для прямой работы AI-агента с открытым **Конфигуратором 1С**: чтение исходников и контекста, подготовка точных изменений, проверка результата и завершение собственных ресурсов.

**Статус: экспериментальный исходный прототип.** В репозитории опубликован выделенный технический снимок. Самостоятельный запуск на произвольной конфигурации пока не проверен; инструкция установки живого сервера появится после такой проверки.

## Что доступно сейчас

| Часть | Состояние |
| --- | --- |
| Технические исходники MCP, native-компонентов и их статических зависимостей | Включены в исходный снимок |
| Контракты команд редактора, план точной замены и протокол результата | 54 синтетических теста без 1С |
| Состав снимка и происхождение файлов | 332 файла с SHA256, 246 Python-файлов |
| Независимый запуск MCP из чистого checkout | Ещё не проверен |
| Универсальная работа с формами, макетами и метаданными | Отдельные будущие сценарии; готовность не заявлена |

Тесты исходного снимка подтверждают только проверяемые контракты и не запускают native-код. Ни один набор проверок репозитория не запускает Конфигуратор, MCP-сервер, бизнес-логику, сеть или подключение к ИБ.

## Проверка рабочего backend — 22.10.2026

В исходном проекте на платформе 8.3.18.1208 принят один маршрут чтения через уже установленного владельца сеанса: два последовательных чтения модуля заняли **392,833 и 398,005 мс на API** (native-часть — 193,424 и 188,224 мс), затем сеанс завершился через `CLOSE`. Подготовка, сборка и установка владельца в эти длительности не входят. Это результаты одного запуска, не универсальный benchmark; сравнение с захватом из хранилища или Vanessa по ним не выполнялось.

Проверка связала интерфейс документа с тем же источником редактора: распознан alias со смещением `+4`, `sourcePointerJoin=true`. Выполнены один `QueryInterface` и один `Release`; возврат `8` означает оставшиеся ссылки, а не ошибку освобождения нашей ссылки. Исходник, владелец, версия и состояние редактора сохранились. Новых записей исходника и ошибок SDK/C++ не было; собственные ресурсы этого нового сеанса закрыты. Это не утверждение об освобождении старых карантинных ресурсов процесса.

**Публичный исходный снимок этой доработкой не обновлён.** Здесь изменена только документация; код рабочего backend и локальные доказательства не перенесены. Чистый clone пока не воспроизводит этот маршрут. Сохранение модуля в конфигурации, обновление ИБ и создание/удаление объектов этим испытанием не приняты.

При выборе следующих решений сравниваем [EditorBridge Mini AI 1C](https://github.com/hawkxtreme/mini-ai-1c/blob/main/tauri-app/src-tauri/src/editor_bridge.rs) с его UIAutomation-маршрутом, [внутренние текстовые интерфейсы Snegopat](https://github.com/infostart-hub/snegopat/blob/master/v8api/textmgr.v) и [каталог инструментов EDT-MCP](https://github.com/DitriXNew/EDT-MCP). Приоритет — использовать подходящие существующие решения с учётом их лицензий. Уникальность архитектуры не заявляется; сторонний код этим обновлением не переносится.

## Переносимые диагностические компоненты — 22.10.2026

В [components/saved-resource-diagnostics](components/saved-resource-diagnostics) добавлены два самостоятельных генератора C: точная проверка типа исключения и ограниченное чтение четырёх байт его числовой причины. Это собственная реализация поверх исследованных структур MSVC и стандартных Win32 API; готовый сторонний код этим изменением не переносится. Сведения о загруженных DLL, рабочие captures и прикладные исходники в компонент не включены.

Отдельный набор тестов компилирует и запускает собственные синтетические C-fixtures с поддельными метаданными и Win32 API. Поэтому он требует C-компилятор; прежние проверки исходного снимка остаются без native-запусков. Компонент по умолчанию запрещает чтение и не предоставляет установки MCP, живого обработчика, разрешений на восстановление, сохранение конфигурации или обновление ИБ. Проверка на реальном исключении платформы и runtime-интеграция ещё не завершены.

## Backend-декодер FileException — 23.10.2026

В переносимый диагностический компонент добавлен `backend_reason_certificate.py`: точная цепочка backend-типа и тот же проверенный алгоритм декодирования в отдельном пространстве имён. Код перенесён побайтно из проверенной реализации; девять прежних функций переиспользованы, нового стороннего кода нет. Пять новых тестов проверяют синтетические метаданные и C без платформенных DLL.

В частной интеграции удалось отдельно измерить обе числовые причины исключений; успешный SavedB/Save и полный рабочий MCP ещё не приняты. В эту публикацию входят только supplied-copy декодер, переносимые тесты и документация. Рабочие captures, локальные профили, native-композиция и разрешения на сохранение не включены.

## Переносимый компонент раннего отказа при ожидании ответа

В [components/early-terminal-feedback](components/early-terminal-feedback) выделен
отдельный reader заголовка pipe. При явно подключённом доверенном callback он
завершает пустое ожидание после подтверждённого отказа, сохраняя состояние
`UNKNOWN`. Уже доступные байты читаются первыми. Частичный, чужой либо ошибочный
callback сохраняет исходный deadline. Автоматический повтор и освобождение
native-ресурсов этим сигналом не разрешаются.

Компонент проверяется переносимыми fake-pipe тестами без Windows API и private
captures. Полсекунды в тесте — моделируемое время, не измеренная скорость 1С.
Исходный снимок332 файлов не менялся; компонент не подключён к нему автоматически.
Полный рабочий backend, проверка live latency и готовый runtime этим обновлением
не публикуются. Статус лицензии прежний.

## Получить код и проверить

```sh
git clone https://github.com/yolatherola/1c-designer-mcp.git
cd 1c-designer-mcp
python -B scripts/check.py --verify-origin
python -B scripts/review_publication.py
python -B -m unittest discover -s scripts -p "test_*.py"
```

Проверки выполняются на Python 3.12 и стандартной библиотеке. `--verify-origin` дополнительно сверяет каждый исходник с первоначальным снимком. После намеренной правки исходников запускайте `scripts/check.py` без этого флага; CI использует такой режим, сохраняя контроль состава и тестов.

GitHub Actions выполняет эти же автономные проверки при push и pull request. `review_publication.py` проверяет разрешённый состав и известные признаки секретов; он дополняет содержательное ревью и не гарантирует отсутствие любых чувствительных данных.

## Ограничения живого backend

Исследования выполнялись в Windows с платформой **8.3.18.1208**. Другие версии и самостоятельный runtime этого снимка не проверены.

Native-профиль сохраняет технические UUID тестовых объектов, локальные пути исходного исследовательского проекта и проверки исторических квитанций. Это известный долг выделения, а не готовые параметры вашей установки. Не запускайте исследовательские launcher-скрипты на рабочей базе и не отключайте guards ради обхода отказов. Для общего запуска нужны конфигурируемый профиль, отдельный каталог состояния и свежий bootstrap.

Сторонние SDK, DLL/EXE и библиотеки не распространяются в этом репозитории. Проверенные зависимости и процесс сборки будут описаны вместе с автономным запуском. Сетевой доступ к рабочему Конфигуратору публикация кода не открывает.

## Структура

```text
source/tools/1c/designer-bridge/   технический снимок прототипа
components/saved-resource-diagnostics/  отдельные генераторы и синтетические C-тесты
scripts/check.py                 SHA, Python AST и синтетические тесты
scripts/review_publication.py    проверка публикуемого состава
SOURCE_MANIFEST.json             происхождение и SHA исходного снимка
ARCHITECTURE.md                  границы ядра, backend и локального профиля
ROADMAP.md                       ближайшие этапы и критерии приёмки
CONTRIBUTING.md                  правила изменений и pull request
PUBLISHING.md                    обновление репозитория и границы публикации
SECURITY.md                      какие данные исключать из issues и PR
LICENSE_STATUS.md                статус лицензии
```

Вложенность `source` временно сохраняет исходные относительные пути. Рабочий backend использующего проекта остаётся в его исходном дереве до независимой приёмки; этот репозиторий пока не подключён к нему как runtime-зависимость. Не ведите две параллельно редактируемые копии backend.
