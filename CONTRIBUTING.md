# Участие в разработке

Публичный репозиторий: https://github.com/yolatherola/1c-designer-mcp. Текущий source — экспериментальный снимок; независимый runtime и граница локального профиля ещё не приняты. Рабочий backend использующего проекта остаётся в исходном дереве до приёмки; не вести две расходящиеся рабочие версии.

Изменение оформлять одним проверяемым сценарием: проблема/триггер → ожидаемый результат → затронутые слои → доказательство проверки. Для bug report нужны версия платформы/Python, код причины, минимальное синтетическое воспроизведение и обезличенные длительности.

~~~sh
python -B scripts/check.py
python -B scripts/review_publication.py
python -B -m unittest discover -s scripts -p "test_*.py"
~~~

Тесты codec/planner/transport работают на синтетическом тексте. Проверка живого backend является отдельной opt-in процедурой на собственном безопасном контуре; общие unit-тесты не подключаются к ИБ и не выполняют бизнес-логику. Не увеличивать список проверок ради числа PASS: проверять изменённые зависимости, затем собранную версию маршрута.

В PR указывать фактически выполненные проверки и ограничения. Локальный unit PASS не означает работу в Конфигураторе. Изменение wire/authority/lifecycle требует проверки отрицательных случаев и явной совместимости версии.

Не публиковать рабочие captures, тексты прикладных модулей, подключения, токены, персональные данные и дампы процессов. Использовать собственные синтетические данные. Правки стороннего кода сопровождать происхождением и условиями лицензии.

Лицензия проекта пока не выбрана: до её утверждения не представлять этот снимок как лицензированный open-source релиз.
